# HW06 Submission Completion Design

## Goal

Bring the HW06 API-testing submission into verifiable alignment with `req/2026.HW06.API Testing_Vi.md` for FR-05, FR-08, and FR-18. Every reported count, run result, defect, link, and commit must be traceable to a real repository artifact or execution.

## Current Baseline

- Each selected FR has 35 AI-generated cases and 10 human-designed additions.
- Detailed verdicts exist, but FR-05 and FR-08 retain duplicate placeholder audit tables, and invalid/incomplete cases have not all been corrected into a final executable suite.
- The Postman collection is valid JSON but contains only eight requests, including two login requests; it does not execute the documented case inventory.
- The collection-level pre-request script correctly injects and logs `X-Student-Id`.
- Newman reports, data files, CI workflow/runs, Excel/PDF deliverables, screenshots, and a reliable exported Git log are absent.
- `src/README.md` has pre-existing user edits that must be preserved while its execution totals and endpoint names are corrected.

## Scope and Evidence Rules

The work will modify submission artifacts under `src/`, add a repository CI workflow, and add only supporting plans under `docs/superpowers/`. Existing unrelated changes in `IMPLEMENTATION_PLAN.md` will not be staged or altered.

Synthetic prompts, backdated commits, invented CI/Newman output, fake issue links, and generated screenshots are out of scope. Audit entries will preserve actual prompts verbatim. Any item requiring an external public URL or human-origin evidence will remain explicitly documented as a manual handoff until supplied.

## Workstreams

### 1. Test Inventory and Audit Corrections

Consolidate each FR into one authoritative audit table keyed by test-case ID. Preserve the original AI case, verdict, technical reason, and a corrected final case for every `INVALID` or `INCOMPLETE` item. Remove FR-06 product-detail cases from FR-05 accounting unless the SUT specification explicitly places them in FR-05. Produce a traceability matrix mapping final case IDs to Postman request/data rows, assertions, and Newman outcomes.

### 2. Executable Postman Suite

Organize the collection into authentication/setup, FR-05, FR-08, FR-18, and cleanup folders. Use data files where one request template can execute multiple partitions safely. Stateful checkout/order scenarios will create isolated fixtures, capture IDs, validate preconditions, and verify postconditions. Negative tests must assert both the response and absence of unintended mutation. Collection-level scripts will retain the student header and expose the case ID in assertion names and console output.

### 3. Real Execution and Defect Handling

Run the collection against `http://localhost:3000` using Newman installed locally for this repository. Save CLI text, JSON, and HTML reports under `src/newman/member-2/`. Derive pass/fail totals from machine-readable output. A behavior becomes a reported bug only after reproducible execution establishes request, expected result, actual result, severity, and evidence. External GitHub Issue URLs and screenshots require the student's manual confirmation or creation.

### 4. CI/CD

Add a GitHub Actions workflow that starts or connects to the EShop SUT, installs Newman, executes the committed collection/environment/data, and uploads reports. The repository will include the workflow and accurate instructions. Public pass/fail run URLs and screenshots will only be recorded after the workflow is pushed and run by the student; a deliberate failing demonstration must be isolated and reverted in real commits.

### 5. Reports and Submission Formats

Synchronize `src/README.md`, the main report, CI/CD report, bug report, AI critique, and AI audit with verified artifacts. Generate an Excel workbook containing cases, audit verdicts/corrections, traceability, and execution summary. Export required Markdown reports to PDF after content stabilizes. The README self-assessment will reflect demonstrated coverage rather than assumed full marks.

### 6. Agent-Skill Deliverable

Improve pseudocode and notes to include parsing, domain/state/security/schema generation, deduplication, human VALID/INVALID/INCOMPLETE review, correction, and export. The existing diagram will not be regenerated by AI because the assignment reserves its design for the student. The student will be asked to confirm or redraw it and provide a video URL only if a real demo is recorded.

## Verification Strategy

Static verification will include JSON parsing, Markdown placeholder scans, case-count checks, ID uniqueness, endpoint consistency, traceability completeness, workflow syntax checks, PDF/XLSX presence, secret scans, and `git diff --check`. Dynamic verification will include Newman execution against the live local SUT and reruns after fixes. Final reported totals must be derived from the latest saved Newman JSON report.

## Commit Strategy

Create focused commits from actual work, normally in this order:

1. Correct test-case audits and final cases.
2. Add executable Postman/data coverage.
3. Add and validate Newman execution artifacts.
4. Add CI workflow and documentation.
5. Complete reports and generated submission formats.
6. Finalize AI audit, agent-skill notes, and exported Git log.

Each commit will stage only files belonging to its workstream. Pre-existing unrelated worktree changes will remain untouched unless the user explicitly assigns them to a commit.

## Manual Handoff

The final checklist will identify only tasks that cannot be truthfully completed locally: confirming the diagram is student-designed, capturing the Postman console screenshot, publishing GitHub Issues, running the public CI pass/fail demonstrations, supplying their URLs/screenshots, optionally recording the Agent Skill video, selecting the self-assessed grade, and creating the final named ZIP after those items are available.

## Acceptance Criteria

- Three selected FRs have at least 35 audited AI cases and at least five clearly identified human cases each.
- Every invalid/incomplete AI case has an explicit correction or exclusion rationale.
- Final executable cases map to Postman requests/data and to saved Newman outcomes.
- Required student header configuration and real execution evidence are present.
- README/report counts agree with Newman JSON and repository contents.
- Required Markdown, PDF, Excel, Postman, Newman, CI, audit, bug-report, and agent-skill artifacts exist or are explicitly marked as a manual external-evidence dependency.
- No placeholder is presented as completed evidence, no credential/token is committed, and the final Git log reflects real commits.
